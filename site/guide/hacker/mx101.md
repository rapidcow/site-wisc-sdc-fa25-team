## Recommendations

(In addition to the expectations outlined in the [home page](../..))

* Follow USENET style bottom-posting.  Trim quotes is good.
  See how mailing lists of [curl](https://curl.se/mail/etiquette.html),
  [MediaWiki](https://www.mediawiki.org/wiki/Mailing_list_etiquette) and
  [the Linux kernel](https://subspace.kernel.org/etiquette.html)
  recommend it.

* Pull request example: [[GIT PULL] BPF changes for 6.17](https://lore.kernel.org/bpf/20250729180626.35057-1-alexei.starovoitov@gmail.com/) ([source](https://news.ycombinator.com/item?id=44731192))

* Patch example: [[PATCH 0/8] builtin/config: introduce subcommands](https://lore.kernel.org/all/cover.1709724089.git.ps@pks.im/)

* Patch revision example: [[PATCH v5 00/14] builtin/config: introduce subcommands](https://lore.kernel.org/all/cover.1714982328.git.ps@pks.im/)

Use the [**git-format-patch**(1)](https://git-scm.com/docs/git-format-patch)
command in both cases (where in the second, you pass `-v5` for your
fifth revision or `-v#` with whatever `#`-th revision), then send it to
wisc-sdc-fa25-team at NONEXISTENT using any MTA you like
(see section below.)

There is a complete walkthrough written by people who made SourceHut:
[git-send-email.io](https://git-send-email.io/).  At the very end you
can submit your own patch and get constuctive feedback from a bot
[here on the list archive](https://lists.sr.ht/~sircmpwn/email-test-drive).


For general email composition:

* Prefer encoding with the quoted-printable CTE if possible.

* Prefer using charset="UTF-8" if possible.

* **Strongly prefer text/plain over text/html.**


## MTA Setup

Either [git-send-email](https://stackoverflow.com/a/68238913/19411800) or
[msmtp](https://jade.fyi/blog/oh-no-git-send-email/) are fine.  Linked are
tutorials to each of these respectively.

If you want to send as your @wisc.edu identity, follow
[this guide](https://www.endfindme.com/memo/mail/auth/xoauth2/#smtp-with-wisc-edu).
Confirm that you have the right token by constructing your
Base64-encoded credentials according to [Gmail's documentation](https://developers.google.com/workspace/gmail/imap/xoauth2-protocol#the_sasl_xoauth2_mechanism)
and try authenticating yourself against `outlook.office365.com:587`
using STARTTLS (*not* SMTPS, that's SMTP+SSL and is for port 465).

Better is to send as your @cs.wisc.edu identity, which
only requires the use of .  Authenticate yourself against
`smtp-auth.cs.wisc.edu:587` using STARTTLS.  Read [this](https://csl.cs.wisc.edu/docs/csl/smtp-auth/)
for information on what your SASL PLAIN username (authcid)
password should be.  Again, [I have a tutorial](https://www.endfindme.com/memo/mail/auth/plain/#smtp-with-cs-wisc-edu)
(though I should point out there was a typo: your username
should be just your `CSLOGIN`, not `CSLOGIN@cs.wisc.edu`
(even though the SMTP server seems kind and forgiving if you
do it either way.))

The same technique works with Gmail but you have to enable
2-Factor Authentication (so setting up a TOTP client would
be a good idea; personally I recommend [Unix password store](https://www.passwordstore.org/)
with the [pass-otp](https://github.com/tadfisher/pass-otp#readme)
extension, but you can use Google Authenticator (or any
Authenticator app really)).  Keep your app password safe as
anyone with access to it would be able to send emails as you.

You can try out [oama](https://github.com/pdobsan/oama), but I'm not
your servant today... figure something that works for you yourself. :)
